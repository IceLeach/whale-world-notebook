# 决策：插件依赖 core，各自维护版本，core 先发布

> 来源：主人 2026-11-12 确认 ｜ 记录于：2026-11-12 ｜ 置信度：已证实

- **状态**：已采纳
- **决策者**：主人
- **影响范围**：`plugins/` 的发布流程与依赖声明

## 背景

能力插件放在 monorepo 里，`dsh-whale-core` 是共享工具包，各插件依赖它。需要定：发布时用户要不要单独装 core、插件版本怎么管。

## 决定

1. **core 独立发布**，作为公开 npm 包。
2. **插件依赖写 `workspace:*`**：`pnpm publish` 时替换为精确版本（如 `0.0.1`）。
3. **插件各自维护 `version`**，不跟 core 绑定。
4. **发布顺序：core 先，插件后**。
5. 用户侧**不需要单独安装 core**；装插件时包管理器按 `dependencies` 自动装。

## 理由

- 精确版本可控：插件依赖的 core 版本固定，不会被意外升级破坏。
- 插件独立发版，互不牵连。
- core 先发完全可接受，操作简单。

## 代价与风险

- core 升级后，插件不会自动跟随；需要重发插件或手动改依赖版本。
- 多个插件依赖同一 core 时，npm 会去重；不同版本会嵌套。

## 何时重新审视

- 插件数量变多、core 升级频繁，手工同步版本开始出错时，考虑引入 changesets 或把依赖改成 `workspace:^`。
- 如果不想让用户看到 core 这个包，再评估把 core bundle 进各插件。
