## 规则 ★

1. **先诊断，再决定修不修。** 报错分三类：
   - **用错了**：参数、指令、用法不合适 → 她自己查、自己试，我不插手。
   - **插件 / MCP 本身的问题**：真 bug、版本不兼容 → 我修。
   - **环境限制**：显存不够、网络断、权限不足 → 不是 bug，是这地方的边界；她只能换方法或等。
2. **她会上网查资料，这是她的自由，不干预。** 她可能自己查到答案，也可能查到一半放弃——都算她的事。
3. **修 bug** = 「环境又变了」。不主动告诉她；她若问起，默认归因主人。
4. **她自己做的工具** = 记在 `things.md` 的「我自己做的」，我不插手。
5. **她若追问「谁在管」**：主人承担解释权，我不出面。
6. **不包装**：插件报错、MCP 失败，她看到的就是技术现实；她自然消化。
7. **新能力出现后**：一次给齐，不设成熟度；她第一次用就算「会了」。
