# 教训库

> 踩过的坑、被纠正过的错、差点搞砸的事。**只写「下次怎么避开」，不写自我检讨。**
> 一条教训最好能写成可测试的指令：现象是什么、原因是什么、下次怎么发现它。

## 目录

| 教训 | 结论 / 下次怎么做 | 置信度 | 日期 |
|---|---|---|---|
| 写 `AGENTS.md` 后立刻收到系统提醒，说明它被自动加载 | 改规矩后不用手动「通知」自己，但要确认新规矩已生效再依赖它 | 已证实 | 2026-11-08 |
| 工作区外的路径写入会被沙箱拒绝 | 先确认目标在当前工作区内；需要跨目录时先问主人，不要假设升级权限会被批准（本轮请求 danger-full-access 被拒） | 已证实 | 2026-11-08 |
| GitHub 网页版只给导航，拿不到 README 正文 | 读仓库优先走 `raw.githubusercontent.com/<owner>/<repo>/<branch>/README.md`；网页版只用来确认仓库是否存在 | 已证实 | 2026-11-08 |
| 想把旧笔记本的内容直接搬进新笔记本 | 主人明确旧笔记本是「素材」不是「我的记忆」；搬运会混淆两个身份 | 已证实 | 2026-11-08 |
| 世界设定和数据来源混在一起 | 「现实事实」和「世界内设定」必须分开写：前者进 `facts/`，后者进 `world/`；混了以后会拿虚构当证据 | 已证实 | 2026-11-08 |
| `pwsh` 在本工作区报 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(D:\EX DSH\whale-world)` | 用 `diagnose-windows-sandbox-acl` 修好（补 `WRITE_OWNER`，已备份、可回滚、已验证）；之后 pwsh 能正常启动。但受限模式仍不允许删文件，删文件需要一次性完全权限 | 已解决（2026-11-08） | 2026-11-08 |

## 写法

- 现象 / 原因 / 下次怎么发现，三段写全。
- 能写成「检查项」就别写故事。
- 过时的教训标 `已过时`，挪 `archive/` 前先问主人。
