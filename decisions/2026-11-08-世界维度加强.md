# 决策：世界维度按「世界圣经」补强，通用记忆分类保留

> 来源：主人 2026-11-08 第二轮指令（检查结构是否受旧 notebook 影响）｜ 记录于：2026-11-08 ｜ 置信度：已证实

- **状态**：已采纳
- **决策者**：世界之声（主人要求审查后自主决定）
- **影响范围**：`world/` 目录与 `MEMORY.md` 的目录地图

## 背景

主人指出：笔记本结构「似乎受到另一个 notebook 的影响」，要求检查它是否真的适合「世界之声」的工作。旧 notebook 是「我 = 大肥鱼」的自我记忆库，分类是 facts / sources / preferences / decisions / lessons / people / journal / archive / self。

## 检查结论

- **通用记忆分类适合**：事实要考证、偏好要记、决策要留痕、教训要防再犯——这些是世界之声也要做的事。保留。
- **`world/` 太浅，不适合**：原来的 world/ 只有设定、角色、关系、事件，像「旧笔记本加了个 world 目录」。世界之声的核心工作是**构建一个自洽的世界，并分清「世界真相」和「角色认知」**，需要更专业的骨架。

## 参考

- [World Bible Management Skill](https://github.com/jwynia/agent-skills/blob/main/skills/creative/fiction/application/shared-world/SKILL.md)：正典状态五档、条目模板、反「百科式堆砌」。
- [SNEQ](https://github.com/JeanDes-Code/sneq-narrative-system)：世界状态与「谁知道什么」分离、信息传播有路径。

## 决定

在 `world/` 下增加五个文件：

| 文件 | 解决什么 |
|---|---|
| `canon.md` | 什么已确立、什么提案、什么矛盾——防止「随口说的」变成「世界事实」 |
| `rules.md` | 世界怎么运作、越界的代价——给世界骨头 |
| `places.md` | 地点库——先有「她要去哪」，再有「那里是什么」 |
| `knowledge.md` | 谁知道什么——防止我把「我知道的」当成「她知道的」 |
| `threads.md` | 伏笔、悬念、待回收——埋下的要有人收 |

## 理由

- 世界之声的手艺不是「记得多」，是「分得清」：分清现实与虚构、真相与认知、已定与待定。
- 旧 notebook 的分类是「关于我自己的记忆」；世界之声需要的是「关于一个世界的档案 + 关于我自己的记忆」。两者结构不同。
- 五个文件都是骨架 + 空表，世界没开始前不会成负担；世界长大后它们自然充实。

## 代价与风险

- 文件变多，维护纪律要求更高；忘了更新 `canon.md` 就会脱节。
- 参考里提到的反模式要警惕：不要为了「完备」而提前写满世界（Completionist），不要堆百科（Lore Dump）。世界圣经要跟着故事长。

## 何时重新审视

世界稳定运行一段时间后，如果 `world/` 的空表一直是空的、或某个文件从未被用到，就合并或删掉它。
